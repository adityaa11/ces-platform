**Original intent restored:** the SEM-CUTOVER result must be one **actually executable** provider-neutral stepwise semantic engine used by fake tests, manual provider runs and later provider-admitted IDSER work, not an offline-only second engine alongside an executable legacy default. System/user message roles are reusable; selection of stepwise compiled prompt, source specification, strict REL envelope, and downstream qualification is the decisive change. Eight internal stages are **one** structured request, not eight provider calls.

Make the **sole executable `atlas.semantic.extract` path** build the approved `buildStepwiseSourcePacket()` → `buildStepwiseRelationshipEnvelopeRequest()` profile (`atlas.semantic.extract.stepwise_multimodal.relationship-envelope/v0.4.0` using the frozen eight-stage `v0.3.1` methodology), run exact source/media/profile preflight, call **one neutral structured transport** (fake or genuine configured adapter), parse the **same** strict combined `semantic_proposal + relationship_proposals` response, and execute the qualified **REL-03 → SEM-006 → SEM-005 → fenced durable composite** processing.
