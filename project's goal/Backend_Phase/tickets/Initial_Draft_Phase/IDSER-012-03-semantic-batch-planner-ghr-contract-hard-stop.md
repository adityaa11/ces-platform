Existing accepted NormalizedDocument v1 in Atlas, durable perceived
  -> temporary, authentic-data-derived GHR body fixture

  -> Atlas-authorized read-only normalizedDocumentRef resolver
  -> verified document, source/perception/hash/grants/REL/media

The *fixture* substitutes only for **future GHR delivery**. It neither mocks accepted document authority nor mocks the batch planner, policy provenance, resolver or durable output. The real GHR implementation later replaces delivery adapters only, subject to separate GO/CK and trusted issuer/route/transactional proof. Atlas's GHR generic header remains separate from the **semantic receiving-domain body**. A body ref/hash alone never authenticates producer, source or reader.

## Final design review — binding implementation clarifications (2026-10-19)

**This section is the current owner precedence over ambiguous legacy wording; it is not GO authority.** Only the three planned leaves below own real implementation. In particular:

- **Input truth:** `NormalizedDocument v1` has page-scoped `textBlocks`, `tables` and `visualRegions`; it does **not** contain a qualified REL/provisional graph. Do not invent one, query an unapproved relational store, or treat speculative structure as accepted semantics. If authorized pre-existing REL revision context is available, bind its exact separate Atlas authority/version; otherwise partition conservatively (keep inseparable source/context together) or explicitly defer/BLOCK when a required dependency cannot be preserved. A known source locator must be canonical `document + page + source-kind + locator-id`, not a naked, possibly repeated block ID.
- **Accepted input read:** `normalizedDocumentRef` is a SHA-256-derived cache key, **not** the `normalizedDocumentFingerprint` or access permission. The latter is the persisted completed-execution fingerprint over canonical accepted NormalizedDocument content. `-03-01` may implement a **narrow new Atlas-owned authenticated read-only resolver** in the existing Atlas trust/data boundary, with exact scope and SQL privilege guards; this is not authority for Bridge to read/write Atlas truth or to invent a second content store. See `-03-01` RC.
- **BSS actual prospective status:** `CapacityPlanningSnapshot/v1` prospective reads may return `status='inactive', reason='prospective_planning_only', view='prospective-planning-only', plan=null` **with valid source/enforcement/process/workload data**. That exact server-authenticated status is usable for *sizing only*, never a BSS active-plan grant, and must not be rejected solely for being `inactive`. Other inactive/unknown/stale/unfit statuses fail closed. Do not require a nonexistent semantic active desired plan before the planner CK; do not deem an unavailable callable BSS reader qualified because a BSS fixture passed.
- **Demand versus provider ceiling:** current `RequestResourceEnvelope` is a numeric **request demand** `{requestUnits,tokenUnits,dayUnits,concurrencyUnits}`, not `{rpm,tpm,rpd,concurrency}` quota-limit metadata. Even when an approved `rpd` provider ceiling is `not_enforced`, a legitimate request may still have positive `dayUnits` demand. Preserve exact BSS envelope shape and separate authorized dimension mask; never encode provider daily limit as 0/infinity or drop the existing demand field. The later `ProviderWorkAdmission/v1` transport API uses a different `{rpm,tpm,rpd,concurrency}` numerical **per-attempt demand** boundary; conversion/admission belongs to separately gated downstream work, not IDSER-012-03.
- **Estimator owner and future SEM:** the current SEM stepwise builder is still **whole-document**, not a qualified batch-scoped packet. IDSER-012-03-02 **may implement a narrow, pure, deterministic, conservative semantic source/request-demand estimator** within this planner scope, with its own frozen evidence-backed version, bounds, and explicit matching BSS-owned workload estimator identity (the BSS owner alone registers/authorizes profile metadata). This is *not* authority for a new SEM prompt compiler, tokenizer claim unsupported by evidence, provider-model selector, BSS quota-planning algorithm, or direct provider call. If neither a qualified existing nor a newly proven bounded estimator can size actual text/table/visual/context/input/output overhead, STOP `SEM_BATCH_ESTIMATOR_GAP` with owner/evidence. Later SEM must separately check final actual batch prompt/request fit and cross-batch meaning. Planner completion does **not** depend on production SEM batch intake.
- **Output and persistence:** GHR body compatibility does not itself mint handoff authority. `-03-03` owns Atlas-domain plan/handoff persistence, deterministic canonical hashing and internal idempotency, **not** Bridge provider-work storage, pg-boss work dispatch, GHR transactional outbox or issuer. For zero eligible source units, return an explicit locally verifiable `NO_ELIGIBLE_SOURCE` disposition with **no** `SemanticBatchPlanReady/v1` body; never invent a fake batch to satisfy positive `batchCount`.
- **Status/precedence:** approved predecessor evidence remains valid; older BSS/IDSER planning contexts mentioning executable `IDSER-012-02` are archival. GHR v0.3's §5.1/§5.2 proposed bodies remain the design target but neither route is live. Once -03-03 passes CK, only the **artifact hard stop** has passed—no semantic execution or accepted meaning is implied.

## Frozen cross-owner rules

1. **Actual source not fake acceptance:** `normalizedDocumentRef` is an opaque cache reference to an accepted Atlas record. Resolver verifies source SHA, perception execution/fingerprint, normalized version, trusted project/workspace/bundle/document, authorization, asset grants and allowed accepted lifecycle state. A read gap is `NORMALIZED_DOCUMENT_AUTHORIZED_READ_GAP`, never direct Bridge SQL or fabricated approved snapshot.
2. **Exact GHR input:** `SemanticBatchPlanInput/v1` body has exactly `normalizedDocumentRef`, `perceptionExecutionId`, `sourceSha256`, `normalizedDocumentVersion`, `normalizedDocumentFingerprint`. No extra required fields or generic-header business keys. Receiver parser rejects unknown keys, invalid hashes and stale/foreign proofs.
3. **BSS capacity ownership:** BSS-005 supplies actual authenticated `CapacityPlanningSnapshot/v1` with structural limits, estimator and qualified prospective process/workload plus provider state and effective-enforcement versions. Do not recreate BSS planning/limiting in IDSER. For Anoman-like RPD unknown, only exact authorized `not_enforced` policy skips daily enforcement; never encode `0`, infinity, an invented daily reset or claim of unlimited provider quota. All enforced dimensions, output reservations, headroom, structural per-request limits and hard interactive reserve remain binding. Unknown mandatory, known zero, stale/revoked/foreign masks, unsupported required dimensions and missing real read fail closed.
4. **Immutable corpus and fit:** Stable structural/per-request fit determines number and composition of batches, not current remaining RPM/TPM/RPD windows. Every eligible locator is owned by one batch; bounded context-only repeats own zero; preserve original language, legends/conditions, REL direction/necessity, media grants and honest deferred dependencies. Transient 429/cooldown only delays later admission; verified structural downgrade requires versioned replan/BLOCKED, never mutation or truncation.
5. **Exact draft GHR output:** `SemanticBatchPlanReady/v1` holds `documentPlanRef`, `planHash`, `batchCount`, `batchHandoffRefs[{batchId,ref,hash}]`. Store document plan + N immutable per-batch handoffs **before** validating this output with a non-executing receiver. The proposed output contract remains inactive/future-owned until authorized by GHR and IDSER/SEM integration. No arrays of provider calls, raw corpus bytes, media bytes, prompts or secrets in GHR/BSS metadata.
6. **Absolute stop:** No GHR issuer/outbox/route/delivery/ack, GHR fan-out, SEM packet intake or prompt builder, BSS provider work/attempt/reservation/transport, semantic stage/acceptance, reconciliation, publication, Master, CES or project-truth effects. Test with non-inert persisted positive control and exact zero forbidden counters.
