# CES-GF-AGB-001 — Agents Bridge: Service Boundary and Contracts

**Phase:** 3D — Central Agent Provider Foundation  
**Parent:** Greenfield Product Suite  
**Status:** Planned

## Goal

Define a centralized agent-provider service boundary that supports the existing
Atlas HTTP provider protocol without turning a model gateway into an
unrestricted general-purpose agent endpoint.

## Work

- Record the service boundary, trust zones, callers, secrets, and data flows.
- Adopt `POST /v1/atlas/analyze` as the first workflow-specific endpoint.
- Reuse `AtlasProviderRequestSchema` and `AtlasProviderResultSchema` as the
  authoritative Atlas payload contracts.
- Define the strict `1.0.0` Atlas HTTP envelope locally without duplicating
  existing request or result definitions.
- Define a bridge-internal Gemini extraction contract that excludes trusted
  source hashes, provider identity, model identity, schema versions, and
  approval state.
- Define deterministic candidate ordering, bridge-assigned IDs, and reference
  remapping.
- Define stable sanitized error codes and HTTP status mappings.
- Update the fail-closed workspace architecture assignment for the new
  application and only its proven dependencies.
- Document how future workflow endpoints can reuse runtime infrastructure while
  retaining separate contracts and prompts.

## Acceptance criteria

- [ ] The boundary distinguishes caller authentication from provider
      authentication.
- [ ] Atlas requires no incompatible CLI or provider-contract change.
- [ ] The design cannot accept arbitrary provider URLs, API versions, models,
      prompts, or response contracts from callers.
- [ ] Trusted metadata is assigned by bridge code, not generated by Gemini.
- [ ] IDs and cross-references have a deterministic normalization algorithm.
- [ ] Human review remains mandatory after successful extraction.
- [ ] Future agent workflows require explicit endpoint contracts rather than
      inheriting the Atlas contract.

## Required evidence

- [ ] Trust-boundary and data-flow document.
- [ ] Envelope and intermediate-schema fixtures.
- [ ] Architecture dependency assignment and boundary test.
- [ ] Error mapping and deterministic ID examples.

## Out of scope

- Network server implementation.
- Gemini API calls.
- Production deployment.
- Non-Atlas workflow endpoints.
